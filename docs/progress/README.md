# Progress notes

One file per change, named `YYYY-MM-DD-short-name.md`: what was built, how it was
verified, and what was **not** verified (compile, offline UI test, live
homeserver, Element, physical Mac, Linux, Windows kept separate).

`PLAN.md` holds decisions, the milestone table and the roadmap. Do not append
change notes to its Progress section: every open pull request editing the same
spot conflicts with the others. Add a file here instead, and update `PLAN.md`
only when a decision or a milestone row changes.

Older notes are in `PLAN.md` and
[`docs/compatibility/PROGRESS-HISTORY.md`](../compatibility/PROGRESS-HISTORY.md).
